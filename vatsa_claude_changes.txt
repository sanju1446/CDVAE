What was broken and what was fixed
1. Lattice collapse (cdvae_model.py — params_to_lattice)
Root cause: The old code had torch.clamp(F.softplus(p[:, 0]) + 0.5) — a bare clamp() with no arguments is a no-op in PyTorch. It does nothing. So a, b, c could collapse to whatever softplus(0) + 0.5 ≈ 1.19 Å and nothing pushed them back.
Fix: (F.softplus(p[:, 0]) + 0.5).clamp(LAT_MIN, LAT_MAX) where LAT_MIN=2.5 and LAT_MAX=25.0. This is a hard physical floor with a gradient.

2. Lattice head not penalized properly (cdvae_model.py — loss computation)
Root cause: The loss normalized a,b,c by their own mean sc = mean(a,b,c). This means if the model predicts a=1.4, b=1.4, c=1.6, sc≈1.47, the normalized targets are a/sc, b/sc, c/sc — and the model matches them perfectly by keeping the ratios right. The absolute scale signal was completely cancelled out.
Fix: Log-space MSE directly on raw lengths: F.mse_loss(a_pred.log(), a_t.log()). If a_pred=1.4 and a_t=6.0, the loss is log(6/1.4)² ≈ 1.97 — a large gradient pointing toward the correct scale.
Added: A volume regulariser F.mse_loss(log(V_pred), log(V_true)) which prevents the cell from having correct individual lengths but wrong volume.

3. Overlap penalty training the wrong thing (cdvae_model.py — overlap penalty)
Root cause: The overlap penalty computed atom distances using lat[i] — the ground-truth encoder lattice (already in correct Å). This gives a useful signal for the score network's position refinement, but does zero to train the lattice head, because lat is not computed from props["lattice"].
Fix: Also compute the overlap penalty using lat_pred_mat = params_to_lattice(props["lattice"]). Now when the predicted cell causes overlaps, the gradient flows back through lat_pred_mat into the lattice head. Minimum separation raised from 1.5 → 1.8 Å and penalty weight raised from 0.5 → 1.0.

4. generate.py — removing the expansion hack
What it was doing: Multiplying each lattice row by ~4.4. Fractional coords do scale with the cell correctly (they're in [0,1)), so atom positions were fine — but the scale factor was estimated from covalent radii (unreliable for mixed compositions) and masked the underlying collapse. It's a symptom fix, not a cure.
Fix: Removed entirely. After retraining with the v4 model, params_to_lattice outputs real Å values directly. A LEGACY_MODE=True flag is left as a stopgap for the epoch-45 checkpoint while you retrain.
